## 实施共同规则

- 在已批准设计上逐阶段实施，使用当前任务分支；不整体合并历史账户分支，不改 unrelated 工作。
- 工程改动使用 TDD：先写真实需求的回归测试并实际运行失败，再做最小实现并运行通过。保存红/绿输出，不能把本轮诊断脚本的断言当成未来实现的红灯证据。
- 使用已有 Node/TypeScript/Electron 依赖和测试运行器，避免引入新 runtime。临时文件放 work/，结果放 outputs/verification/1.3.0/。
- 新测试自动被 `scripts/test.mjs` 发现。单文件验证命令为 `node --import tsx <测试路径>`；全量为 `npm run check`。下文新增文件是计划，不表示已经存在。
- 新日志仅用合成或脱敏资料；不要复用历史测试账号、环境变量或旧 vault 来自动登录。
- UI、真实 Session、代理和持久化要运行验证，不能仅检查源码字符串。
- 验证通过后提交中文提交说明，只暂存任务文件；合并 main、发布和处理其他分支不属于本设计授权。
