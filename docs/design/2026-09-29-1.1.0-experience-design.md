# JMComic Desktop 1.1.0：标签、动效、视觉与下载设计

日期：2026-09-29。基线：本地 main 的 `8366ed4`，即上一会话合并的 1.0.7 实现。工作分支：`feat/experience-1.1.0`。

状态：**用户已于 2026-09-29 明确批准“开始实施”**。本文描述计划交付的 1.1.0，不能当作已实现功能或验证报告。用户补充的设置页滚动区缺陷已经单独按 TDD 修复，证据见[修复记录](../../outputs/2026-09-29-sidebar-layout-fix.md)。实施进度见[实施清单](../plans/2026-09-29-1.1.0-execution.md)。

## 1. 目标与现状

将现有功能合成一个版本号一致、能够直接运行的 1.1.0：成熟的阅读标签操作；覆盖整个界面的轻量动画；一致的桌面视觉；独立动画与 GPU 设置；图片 / PDF 下载。保留现有在线获取、收藏与历史、离线图片库、CBZ、保存失败保护、阅读锚点和下载恢复能力。

当前代码与上一会话核对后的重要事实：

- 阅读标签已有 X、左右方向键、Home/End、Delete；还没有新建、拖拽、右键管理或关闭恢复。`ReaderWorkspace.tsx` 与 `appStore.ts` 是扩展入口。
- 只有活动标签挂载阅读会话，后台标签仅保留元数据。隐藏侧栏则保留活动会话及图像；这两种资源策略不能混淆。
- 切换 / 关闭先等待进度与偏好保存，失败保留原标签；关窗冻结入口并排空任务。新交互必须沿用这些保证。
- `PageHost` 以 display 切换，`AppFrame` 以 hidden 切换布局；当前零散 hover / opacity 效果没有统一页面和布局过渡。
- SettingsPage 把 `maxWidth:720px` 限制加到了滚动容器。实际复现显示父浏览区域已扩展到 x=1280，滚动容器仍结束于 x=784。已将宽度限制下移至内容区。
- 自动收起导航与用户手动选择共用一个字段。整体布局改造需区分这两者，隐藏阅读时恢复用户原先的导航选择。
- 已有 GPU 功能和进程性能诊断，没有独立硬件加速设置；数据库设置在 app.ready 后加载，不能直接用于 ready 前的 GPU 开关。
- 下载记录严格对应一章图片目录，图片齐全就 completed；本地阅读、缺页检测、删除和打开目录均依赖此契约。
- `package.json` 仍为 1.0.6，1.0.7 成品通过构建参数覆盖；CHANGELOG 已有旧的“1.1.0 推荐”条目。正式交付时统一源码、锁文件根版本、更新日志、关于页、文件版本和 EXE 名称。

## 2. 成熟产品对照与功能取舍

Edge 的新建、关闭、恢复和切换快捷键，以及标签固定、分组和节省后台资源的做法可供参考；VS Code 的工作台将导航、内容与编辑标签分开。这里继承它们的可预测交互，阅读器保持一个活动内容会话。[Edge 快捷键](https://support.microsoft.com/en-us/edge/keyboard-shortcuts-in-microsoft-edge)、[Edge 标签分组](https://www.microsoft.com/edge/features/tab-groups)、[Edge 休眠标签](https://www.microsoft.com/edge/features/sleeping-tabs)、[VS Code 界面](https://code.visualstudio.com/docs/editing/getting-started/userinterface)。

| 能力 | 1.1.0 决策 | 行为 |
| --- | --- | --- |
| 新建、关闭、切换 | 实现 | 标签栏固定 +；每项独立 X；中键关闭；关闭后台项不影响活动阅读 |
| 拖动排序 | 实现 | 按稳定 ID 排序；拖动预览、落点提示、窄栏边缘滚动；Esc 取消；松手只提交一次顺序 |
| 右键编辑 | 实现 | 重命名 / 恢复原名、固定 / 取消固定、关闭、关闭其他未固定、关闭右侧未固定、查看作品详情 |
| 关闭恢复 | 实现 | Ctrl+Shift+T；最多 20 项内存关闭栈，恢复原来源、章节、位置和标题；已打开作品去重 |
| 溢出管理 | 实现 | 最小可读标签宽度、水平滚动、活动标签滚入可见区域、全部标签列表与标题筛选 |
| 键盘与可访问性 | 实现 | 标准组合键、tablist 语义、明确焦点、右键菜单可用键盘、拖动有键盘替代 |
| 会话恢复 | 实现为可选设置 | “启动时恢复阅读标签”默认关闭；启用后只恢复标签描述，选中活动阅读时才取图 |
| 多窗拖出、标签分组、垂直标签 | 本版不加入 | 会引入多阅读会话和跨窗口保存所有权；现有三栏已有常驻导航，先交付完善的横向管理 |
| 复制同一本同来源标签、网页刷新 / 静音 | 不加入通用浏览器命令 | 同书同来源继续复用；重试针对章节加载或单页错误，避免多个标签争写同一阅读历史 |

固定标签集中在左侧，普通拖动不会悄悄改变固定状态；右键或快捷操作明确固定。固定项仍可通过独立关闭入口关闭，批量“其他 / 右侧”跳过固定项。右键菜单标出受影响范围。

关闭当前项优先选右邻、再选左邻。关闭最后一项回到浏览区，应用工具区仍保留“新建阅读标签”入口。隐藏侧栏保留所有标签；关闭是独立动作。切换、批量关闭和正常关窗的保存失败都保留可重试现场。

### 2.1 新标签页

内容以本地已有数据为主：紧凑搜索框、继续阅读（最近 6 项）、我的收藏、离线书库、最近关闭（展示最多 5 项）。没有历史时展示简洁引导，不伪造记录，不自动加载一屏网络推荐。

- 搜索作品名称跳转中间搜索页；输入有效作品编号跳转详情。保留新标签作为即将阅读的目标，确定章节后再打开。
- 从继续阅读打开作品，在活动新标签中替换为阅读标签。已有相同作品与来源时激活已有标签，不创建重复阅读会话。
- 点击 + 总是创建可关闭的新标签并聚焦搜索框；空标签用独立 UUID。新标签不挂 ReaderPage，也没有阅读保存器。
- 阅读标签以作品 + online/local 来源去重；标签 UUID 与内容去重键分开，便于起始页替换、关闭恢复和标题管理。
- 自定义标题只写标签元数据，不修改真实作品名或阅读对象，避免重新加载与污染历史。

### 2.2 快捷键边界

| 操作 | 快捷键 |
| --- | --- |
| 新标签 | Ctrl+T，即使侧栏隐藏或没有标签也可打开 |
| 关闭当前阅读标签 | Ctrl+W；没有标签时不退出整个应用 |
| 恢复最近关闭 | Ctrl+Shift+T |
| 按排列切换 | Ctrl+Tab / Ctrl+Shift+Tab |
| 直达标签 | Ctrl+1…8；Ctrl+9 为最后一项 |
| 标签内聚焦 / 切换 | 左右键、Home/End，沿用可访问的 roving focus |
| 移动标签位置 | Ctrl+Shift+PageUp / PageDown |
| 打开标签菜单 | 右键、Shift+F10 / Menu 键 |
| 退出当前局部交互 | Esc 先取消拖动 / 关闭菜单或弹窗，再退出全屏 / 铺满 |

输入法组合输入、普通文本编辑、模态窗口打开时，不抢占局部快捷键。模态优先，关闭标签快捷键只能作用于阅读工作区；不调用窗口关闭。动作结束后恢复目标标签或阅读视口焦点。标签名过长通过可访问提示显示完整名称。

## 3. 布局与状态架构

继续使用 React、Fluent UI、Zustand、现有图片协议和阅读器，不重建 UI 框架。扩展 `ReaderTab = StartTab | BookTab`，公共字段为 id、customTitle、pinned；BookTab 持有原 reader state 与 contentKey。关闭栈、顺序、活动 ID 与保存屏障由独立 workspace 模块管理，再由 store 暴露动作。

**必须修掉潜在并发冲突**：现有 `transitionReader` 在等待 saver 之前读取 tabs，之后写回旧数组。新增排序、固定或重命名若同步修改 store，会被迟到保存覆盖。所有标签变更进入统一串行队列，保存后读取最新状态并按 ID 合并锚点；拖动过程只改临时视觉，不在每个 pointermove 写全局状态。排队切换可以合并目标，关闭 / 保存动作不得跳过。

可选会话恢复存到有版本和数量 / 长度上限的本地工作区状态；不保存图片、Canvas、原始网络响应或认证信息。只在语义动作完成后写入，读取校验无效项后降级为空工作区。恢复失败不覆盖原快照。关闭栈不跨重启保留。个人数据导出 / 清除同时处理用户选择保留的工作区状态。

导航状态拆成用户偏好与阅读布局的临时自动收起。进入阅读时临时使用 64px；隐藏 / 最后关闭时解除临时状态；用户本来收起的导航仍收起。用户在阅读中显式改变导航时，后续布局切换尊重该选择。

中间区和阅读区之间增加可拖动分隔条，支持键盘调整、双击恢复默认比例，保存比例而不是屏幕像素。宽窗口默认约 40/60；中间最小 300px、阅读最小 480px，窗口最小值沿用 960×640。窄窗口导航用临时浮层，分隔拖动有约束，放手后保存；阅读锚点在开始 / 结束采样时保持一致。

浏览滚动容器占满实际栏宽，内容可在容器内设置可读最大宽度。设置、诊断、列表、详情均按所在容器响应，不能仅以屏幕宽度判断三栏内的可用空间。滚动区的恢复与导航状态分别测试。

## 4. 全局动效清单

统一 motion tokens：反馈 90–120ms、内容过渡 150–180ms、较大布局 180–220ms，普通动画上限 250ms。进入采用快速响应后缓停，退出更短；同一种表面从同一方向出现和退回。这是本项目目标值，实施时通过测量调整，不是实测成绩。[Windows Motion](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/motion)。

| 区域 | 动效 | 资源与行为约束 |
| --- | --- | --- |
| 首次窗口内容就绪 | 内容短淡入 | 原生窗口的最小化 / 最大化由系统负责；不延迟可操作时间 |
| 主导航选中 / 悬停 / 按下 | 颜色和选中标记短过渡 | 小区域重绘；不跟随鼠标持续运算 |
| 首页、分类、搜索、收藏、下载、设置、诊断切换 | 轻微位移 + 淡入；返回方向一致 | 保持最多 3 个主页面缓存；活动页立刻响应；退出页 inert |
| 详情进入与返回 | 6–10px 位移 + 淡入 | 不复制整页封面或扩大缓存；保留列表滚动位置 |
| 阅读标签新增 / 关闭 | 标签条内短淡入 / 离场与邻项位移 | 先保存成功再关闭；仅复制轻量标签外壳，不保活第二套图片 |
| 标签切换 | 选中态过渡、内容短淡入 | 只有一个 ReaderPage；不对整章跨层交叉淡入 |
| 标签拖动 | 跟手位移、相邻标签 FLIP、落点提示 | 每帧最多一次测量 / 更新，取消与结束释放临时层 |
| 两栏 ↔ 三栏、侧栏显隐 | 短平移 / 裁剪呈现最终布局 | 最终宽度先落定一次，避免逐帧改 flex-basis 触发阅读重排 |
| 铺满 ↔ 还原、导航展开 | 使用同一布局过渡协调器 | 屏幕 / 系统全屏不做重复窗口动画；保持活动会话和页内锚点 |
| 阅读工具行、目录与进度菜单 | 从对应入口短展开 / 淡出 | 工具显隐仍由用户点击或 H；不因鼠标移动弹出，不遮漫画 |
| 右键菜单、下载格式选择、选章、偏好弹窗 | 轻量缩放 / 位移 + 淡入淡出 | 优先复用 Fluent；焦点管理与退出可取消，不能依赖 transitionend 才完成保存 |
| 封面与阅读图片加载 | 预留尺寸后一次短淡入 | 只对首次可见解码；虚拟滚动重新挂载不重复炫动；不逐卡片大规模 stagger |
| 下载进度、状态消息、错误重试 | 进度条 scaleX / 状态轻微过渡 | IPC 进度合并；不以假的“100%”掩盖 PDF 生成阶段 |
| 空列表 ↔ 内容、筛选结果 | 容器短淡入 | 不对几百项逐个定时动画，不抢搜索输入 |
| 主题切换 | 小区域色彩过渡，阅读画布稳定 | 不截图整窗口转场；reduced-motion 时立即完成 |
| 加载中 / 最小化 / 后台 | 必要加载反馈；不可见时暂停 | 关动画时用静态状态文案；不维持纯装饰循环或全局 rAF |

实现以 CSS 和 Web Animations API 为主；有限元素使用 FLIP，不增加重型动画库。优先动画 transform / opacity，结束释放 will-change。不会给全部卡片、图片和 Canvas 永久强制 GPU 合成。[浏览器动画性能](https://web.dev/articles/animations-guide)。

阅读视口的 ResizeObserver 会重算页尺寸与虚拟列表，因此不能为 220ms 动画每帧改变真实阅读宽高。布局协调器在开始记录页码 / 页内比例，提交最终几何，再对外壳进行短过渡；图片不持续缩放。动画取消、连续切换、组件卸载均有 finally 清理，焦点 / inert / hidden 状态同步。若某种几何效果测出额外长任务，收敛为短平移淡入。

## 5. 动画与 GPU 独立设置

| 设置 | 默认与生效 | 说明 |
| --- | --- | --- |
| 界面动画 | 开启；立即生效 | 系统 prefers-reduced-motion 优先；关闭后保留必要状态反馈并立即提交布局 |
| 硬件加速 | 开启；重启生效 | 允许 Chromium 在支持的硬件 / 驱动上选择合成和光栅化路径 |
| 实际运行状态 | 只读 | 展示已启用 / 软件回退 / 检测中 / 读取失败，以及待重启设置；高级细节在诊断页 |
| 启动时恢复阅读标签 | 默认关闭 | 只恢复轻量描述，避免自动下载多本书 |

四种动画 / GPU 开关组合都要正常使用。关闭动画不关闭 GPU，关闭 GPU也不隐式改写用户动画偏好；GPU 软件回退时自动采用更轻的位移 / 淡入，避免模糊等昂贵效果。

Electron 要求 `app.disableHardwareAcceleration()` 在 ready 前调用，GPU 实际状态在 `gpu-info-update` 后读取。因此新增仅存启动图形偏好的小型 `startup-preferences.json`，放在 `getAppDataDir()` 对应的数据目录；主进程顶层同步读取有尺寸上限的文件。缺失采用默认；损坏保留原文件并使用默认，显示可理解的诊断。使用原子写入，文件中不存代理、认证或阅读数据。该字段不与数据库双向镜像，避免两个来源不一致。[Electron app API](https://www.electronjs.org/docs/latest/api/app#appdisablehardwareacceleration)。

窄 IPC：获取图形设置 / 实际状态、设置布尔值、显式重新启动。设置写入失败必须反馈，不显示已保存；重启先走现有关窗保存与下载停止屏障，成功后才安排 relaunch，保存失败留在原窗口。没有自动定时重启。

兼容策略基于 Chromium 的默认检测和回退，不依赖 GPU 厂商 / 型号，不强制独显、不关闭驱动黑名单，不假定 WebGL 就等于界面合成。Intel / AMD / NVIDIA 的核显与独显走同一设计路径。驱动禁用、远程桌面或硬件不支持时，**不能保证实际 GPU 加速，必须软件回退并如实显示**。单台机器验收不宣称所有显卡均已实测。Mica / 亚克力依旧可选，低资源及回退路径采用可靠纯色表面。

## 6. 视觉体系

推荐“轻量桌面阅读工作台”：暖白 / 石墨中性色、克制的蓝色操作强调、细分隔线；阅读画布保持安静的深色。保留 Segoe UI / 微软雅黑系统字体，主文字 14px、辅助文字 12px、页面标题 20–24px，统一 4/8px 间距尺度和 6/8/12px 圆角。文字对比至少 4.5:1，必要控件和焦点边界至少 3:1，支持高对比与键盘操作。

| 表面 | 改造重点 |
| --- | --- |
| 标题栏 / 导航 / 状态栏 | 同一视觉密度、图标笔画和焦点风格；图标均有名称；状态栏次要信息低干扰 |
| 首页 / 分类 / 搜索 | 一致的标题和筛选层级；封面比例稳定；骨架、错误、空状态同体系 |
| 收藏 / 历史 / 离线库 | 优先继续阅读与进度；清晰区分在线记录、图片离线内容和 PDF 成品 |
| 作品详情 | 按中栏宽度排版，压缩重复标题；章节行高度、选中态和下载入口一致 |
| 阅读器 | 40–44px 紧凑标签栏；页码与工具在固定区域；工具默认收起；降低面板边框噪音 |
| 下载 | 同一任务列表展示图片和 PDF；明确阶段、范围、文件状态、重试与打开入口 |
| 设置 / 诊断 | 滚动区全宽，表单内容居中；按外观、阅读、下载、网络、存储、诊断分组；深色控件不出现零散浅底 |
| 弹窗 / 菜单 / 提示 | Fluent 交互原语与统一表面；按钮主次清楚；状态不只靠颜色表达 |

## 7. 图片 / PDF 下载

### 7.1 用户操作与输出

设置增加 `downloadFormat: 'ask' | 'images' | 'pdf'`，界面为“每次询问 / 逐张图片 / 合并 PDF”，默认 ask，旧设置没有字段也按 ask。每次新下载请求仅询问一次，多章不逐章弹窗；有默认格式时直接沿用，入口的更多操作仍可临时选另一格式。对话框可勾选“以后默认使用此格式”，只有确认才保存，取消不创建任务。

覆盖详情页总下载、章节行下载、阅读器下载本章，以及单章作品直接下载这四种路径；统一请求入口，避免其中一处绕过询问。重试 / 续传使用任务已保存格式，之后更改默认不影响已有任务。已有图片不能阻止另存 PDF，已有 PDF 也不能将图片按钮标成“已离线保存”。

一次选择同一部作品的 N 章，PDF 按章序和页序合成**一个 PDF**；单章就是一个 PDF。每张原图对应一页，保留宽高比、不裁切，PDF 页尺寸随图像比例调整；超长图缩放坐标到 PDF 合法尺寸但不主动降低像素。PDF 加章节书签便于跳转，不加额外封面页。多部作品各一份，不能混成同一文件。

| 格式 | 最终输出 |
| --- | --- |
| 图片 | 保持现状：配置下载根目录 / manga-ID / chapter-ID / 页号.格式；旧记录继续读取原目录 |
| PDF | 直接位于配置下载根目录，例如 `JMComic/山间来信 [JM101] 第1-3章.pdf`；没有作品子目录 |

非连续选章文件名使用“选 3 章”加稳定短标识，防止与完整范围混淆；非法文件名、保留名、长度限制统一处理。任务创建时固定根目录和最终文件名。同名文件采用不覆盖的编号后缀，并在发布前处理竞争；不覆盖原文件。下载页的 PDF 项显示选章范围、文件大小、打开 PDF / 显示所在文件夹；打开使用系统 PDF 阅读器。当前应用的图片阅读器不直接接收 PDF 文件。

### 7.2 下载架构与失败处理

保留现有图片 downloads 表和图片离线库，增加 `pdf_downloads` 聚合任务表。最少字段：ID、作品信息、有序选章清单、根目录快照、最终文件名、任务自有暂存 ID、阶段、总 / 已下载 / 已生成页数、错误、时间与请求去重键。选章清单必须在网络请求前完整持久化。选章数组、标题和地址在 IPC 主进程校验。

统一 UI 命令标识 `{ kind: 'images' | 'pdf', id }`，防止两个表数字 ID 相同导致误取消 / 删除。PDF 去重包含作品、有序选章、格式和根目录；图片去重保留现状。共享网络调度和下载并发预算，PDF 最多一个合并工作器；新增任务不能让总网络并发翻倍。

流程为：持久化任务 → 解析选章 → 获取 / 反打乱图片 → 验证所有页 → 逐页生成 PDF → 校验并发布文件 → 标记完成 → 清理本任务中间产物。进度分成“获取图片 x/y”和“生成 PDF x/y”，总量尚未知时明确显示处理中。图片齐全不能提前写 PDF completed。

推荐使用成熟 Node PDFKit 的流式输出，运行在独立工作器，逐页读取 / 解码；不向渲染器传输整本图片，不把整本拼成长 Canvas，不一次把全部文件读入内存。PDFKit 支持 JPEG / PNG，其他格式先复用现有解码能力转成兼容格式。安装前检查官方 npm 包、版本、传递依赖和预计总下载量，仅增加必要依赖与锁文件；正式包须验证 worker 和依赖均包含。[PDFKit 流式输出](https://pdfkit.org/docs/getting_started.html)、[PDFKit 图片支持](https://pdfkit.org/docs/images.html)。

暂存图片放应用数据目录下每个 PDF 任务自有的 staging 目录；最终 `.part` 放目标下载根目录，以便同卷发布。失败 / 取消保留可重试页并移除未完成 PDF，任务删除时清理自己的暂存；成功后清理自有图片，用户最终只看到根目录 PDF。不能清理或移动原有图片库。

PDF 只在流关闭、必要完整性检查和 flush 成功后发布。输出提交使用不会覆盖现有文件的独占策略，不能依赖 Windows rename 的覆盖语义；目标冲突分配新后缀。任务状态与最终文件之间的崩溃窗口，通过保留 committing 阶段、文件大小 / 摘要 / 页数和任务标识协调：启动检查任务自己的成品再修正状态，未验证时不报完成。

失败原因包括网络、缺页、解扰 / 解码、磁盘满、目标不可写和文件被占用；均保留重试入口和已完成页。更换默认目录不迁移已有任务；重启将未完成阶段恢复为可续传，合并从已验证的暂存页重建。取消与关闭通过 AbortSignal / worker 终止协议并等待结束，禁止迟到回调发布文件。

新增单文件路径校验，要求 PDF 的实际父目录是任务记录的根目录，校验 junction / reparse 风险。不能放宽当前“图片两级目录”的安全规则，也不能把下载根目录传给递归删除。

个人数据备份 / 导入 / 清除的白名单增加 PDF 任务描述，保持旧备份兼容；导入未完成任务先置为待用户恢复，不自动联网。清除记录和删除产物保持各自现有的明确操作含义。PDF 临时任务、图片下载和现有 CBZ 的停止 / 恢复一起接入 shutdownController。

## 9. 验收与性能目标

以下均为待执行的验收要求，不是已经取得的结果。

- 标签：真实指针拖动、中键、右键、快捷键；1 / 2 / 20 / 50 标签，长标题和窄栏溢出；固定分区、批量关闭、重复恢复、保存失败、快速连续切换、保存等待时排序 / 改名不丢更新。
- 起始页与会话：无数据 / 离线 / 删除本地文件 / 历史已变化；创建多个空标签；同书去重；恢复元数据时后台不发图片请求；关闭失败不进入关闭栈。
- 阅读回归：单页 / 滚动、跳页、缩放、切章、工具行、全屏、目录、单页重试、背景释放、保存失败 / 冷启动续读。标签改名 / 排序不重挂活动 Reader；布局变更页内偏移误差目标 <1%。
- 布局：960×640、1280×860、1600 宽，100 / 125 / 150 / 200% DPR，浅 / 深 / 高对比；隐藏与恢复后滚动容器、导航偏好、焦点与阅读锚点正确。对正在动画的退出区域验证 inert 和 Tab 顺序。
- 动效：动画 / GPU 四种组合；系统减少动态效果；启动、布局、页面、菜单、加载、下载等表中全部区域。快速开关与连续输入不会积压动画，关闭动画不依赖动画完成事件。
- GPU：设置写失败、缺失 / 损坏启动配置、重启取消、软件渲染强制测试和实际状态读取；记录每个真实测试环境。跨厂商未实测的组合在报告中标为未实测。
- 性能消融：固定素材与相同可见区域，分别比较动画开 / 关、GPU 开 / 关，预热后至少 30 次页面 / 侧栏 / 标签循环。记录输入到首反馈、帧间隔分布、>50ms 长任务、renderer 堆、全进程私有内存及峰值、图片请求与 Canvas 数量。
- 性能目标：本机支持路径下关键交互首反馈 p95 <100ms；60Hz 场景过渡帧间隔 p95 目标 ≤20ms（rAF 只作代理，结合 trace 核验，不当作真实呈现帧率保证）；同场景动画开启不引入额外的重复取图 / 解码。静止 30 秒后装饰动画和常驻动画 rAF 数为 0，关闭 / 切换 50 次后资源不持续增长。未达标优先简化效果，不提高 GPU 占用强行维持效果。
- PDF：单章 / 多章 / 非连续选章顺序；JPEG、PNG、WebP、透明、横图 / 长图；缺页 / 解扰失败；取消 / 重启；磁盘不足 / 同名 / 路径变化；最终根目录只有对应 PDF；图片路径、缺页修复与 CBZ 保持可用。生成合成样章 PDF 后用标准 PDF 解析器验证页数 / 顺序 / 尺寸，再渲染逐页目检，与输入逐页对照；大任务测主界面响应与峰值内存。
- 交付：npm test、typecheck、生产构建和包内依赖检查；便携版、目录版各直接启动并完整退出，验证内置版本、图标、下载和恢复；不能仅用 Electron 加载 app.asar 代替 EXE 验收。

真实站点 CDN 速度与成年确认仍需要独立实网证据；合成网络只能证明应用内部链路。需要本人完成的站点确认由用户自行操作。
