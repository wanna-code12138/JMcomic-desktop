# JMComic Desktop 1.2.0 外观优化研究与设计

日期：2026-10-02。研究基线：`a5b40e2`，源码版本 `1.1.0`。设计分支：`feat/ui-1.2.0-design`。

状态：**研究方案，待审阅，未实施产品变更**。本轮交付系统性视觉方案、现状证据、兼容边界及设置区域的局部外观草图。版本号、配置、应用代码和用户数据均未改动。

建议 1.2.0 延续现有 Fluent 桌面阅读风格，通过语义色、文字层级、控件对齐、表面层次和状态呈现提高完成度。功能、入口、信息顺序、阅读布局及当前动画机制作为兼容基线；优先解决全局一致性，再逐页精修。

## 目标与边界

本版的目标是让同类元素看起来属于同一个产品：主次信息清晰，浅深主题完整，窄浏览栏下仍然整齐，阅读区保持安静。成功应能在同内容、同状态、同窗口尺寸的前后对照中看出来，也应有功能与动画回归证据。

允许的变化包括颜色、字体角色、图标一致性、描边与阴影、非阅读内容区的留白、控件内部对齐、对话框静态皮肤，以及不改变信息顺序的视觉分组。

冻结范围包括现有页面和入口、操作步骤、快捷键、Tab/筛选语义、数据与保存流程、下载格式、主题和 GPU 设置行为、阅读会话挂载策略、图片加载策略、动画触发条件、时长、缓动、位移规则及退出释放机制。新的配色会改变颜色过渡的端点，但不改变过渡属性和时间；不会把所有现有动效重新收敛成一套新节奏。

本方案不引入新 UI 框架、动画库、外部字体或图标包。复用 React、Fluent UI、已有 Fluent 图标、语义 CSS 和现有测试。新版号调整及发布工作留待实际实施和发布阶段，不属于本轮研究。

## 当前界面已有的基础

- 主导航为展开 208px、收起 64px，标题栏 36px，阅读标签栏 44px；三栏职责明确。
- 首页、分类、搜索、收藏及下载封面区域普遍采用最小 180px 的网格、16px 间隔和 3:4 封面比例。这部分已经一致，首轮保持。
- 已有浅深色语义变量、蓝色强调色、4/6/10px 基础圆角、Fluent Provider 主题及 `surfaceStyles.ts`，无需另建庞大的设计系统。
- 设置页内容最大宽度 672px，诊断页 880px；滚动容器占满所在栏，内容在内部限宽。两个宽度服务不同信息密度，保留各自用途。
- 详情页已有按浏览容器 580px 断点的适配。阅读器已有固定深色画布、工具栏收起、铺满/全屏、页内锚点和单活动会话保护。
- 当前有 CSS 与 Web Animations API 两条动效路径，并有动画/GPU 独立设置、减少动态效果、退出 inert 和动画超时清理。

## 视觉方向比较

以下是设计判断，不是用户测试结果。

| 方向 | 外观与取舍 | 对本项目的适合程度 |
| --- | --- | --- |
| **精修 Fluent，推荐** | 中性浅底、石墨深色、克制蓝色、清晰字体层级；普通区域少阴影，浮层有明确层级 | 能复用现有体系，收益覆盖所有页面，保持桌面熟悉感和既有动效最容易 |
| 柔和书库 | 浅色偏暖、文字和封面更有书籍排版感，留白略多 | 可借鉴辅助信息的克制处理；大范围暖色和更疏布局会改变当前气质与一屏信息密度，不作为默认整包替换 |
| 紧凑工作台 | 更强分隔、更密集列表、更明确的工具区域 | 适合下载与诊断局部；全局采用会使阅读软件显得拥挤，且更容易改动标签和控件几何 |

推荐用第一种作为全局规则，吸收第二种的文字层级和第三种的数值对齐。避免把三个方向各分配给不同页面，造成新的风格分裂。

官方依据支持的是方法而非这份方案的具体配色：[Fluent 设计变量](https://fluent2.microsoft.design/design-tokens)用全局值与语义别名控制颜色、文字和间距；[Fluent 字体层级](https://fluent2.microsoft.design/typography)强调可扫读的角色与基线；[Windows 表面层级](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/layering)区分应用底层与内容层。具体方案仍须在 JMComic 的真实页面中验证。

## 系统性设计规则

### 颜色按用途定义，并成对验收

保留现有品牌蓝和应用图标，优先减少大面积底色的蓝灰感，让封面成为内容区的主要色彩来源。浅色候选底色采用接近 `#f3f4f6` 的中性灰，内容表面保持白色；深色延续现有石墨蓝灰家族。候选值以草图和真实主题对照为准，不将一次整体降饱和代替逐层设计。

在现有变量之上补足用途区分：基础/内容/浮层表面，主要/次要/辅助文字，普通/必要控件边界，品牌前景/实心品牌填充/填充前景，选中状态、成功、警告、失败。收藏状态应有稳定语义映射，避免一个页面使用 `#ff4d4f`，另一个依赖危险色。

两套主题保持相同语义，不简单反转浅色。hover、pressed、selected、focus、disabled 都按前景与实际背景一起检查。半透明背景按实际合成结果核对，不能仅计算前景对未合成色值。

普通文字以 4.5:1 为最低验收值；识别控件和状态所必需的非文字视觉线索以相邻颜色 3:1 为最低值。装饰性卡片分隔线无需一律加深到 3:1，以免过度描边。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

### 文字与间距形成少量角色

保留本地系统字体栈。让全局 CSS、Fluent 控件和自定义控件使用一致的中文回退与字重，不下载新字体。

| 角色 | 拟采用的默认规则 | 适用与限制 |
| --- | --- | --- |
| 普通页面标题 | 24px / 32px，600；窄内容区 20px / 28px | 只处理原来有标题的页面，不给 Tab 页面增加重复大标题 |
| 分组标题 | 16px / 22px，600 | 设置、章节分组等；详情书名可保留独立标题角色 |
| 主体与操作 | 14px / 20px，400 或 600 | 卡片标题保留两行上限和现有可见信息量 |
| 辅助说明 | 12px / 18px，400 | 路径、作者、状态说明；不靠整体透明度降低可读性 |
| 紧凑工具与标签 | 维持现有字号和容器高度，统一颜色/字重 | 避免本轮改变标签溢出阈值、关闭动画几何和工具栏占位 |

以 4/8px 为主要间距节奏，复用当前 16px 网格间隔、24px 浏览页边距与窄栏既有边距。图标通常沿用 16/20px，普通按钮延续现有尺寸。对齐和统一内边距优先于把所有控件做大。不会为了整数刻度修改已与动画或阅读算法绑定的 5px、6px、12px 等值。

### 表面层级保持克制

应用外壳、内容区、悬浮菜单和对话框有清晰但有限的明暗差。普通内容卡片使用细边界，不给每个区块都加外阴影；弹出层保留必要阴影和边界。高亮集中在当前选中项与主要操作，普通信息标签降低强调。

基础圆角先保留 4/6/10px；对话框等特殊角色集中约定，不做全局替换。现有 Mica 与纯色窗口选项和回退保持原样，不增加 CSS 全窗模糊、发光或额外合成层。[Fluent elevation](https://fluent2.microsoft.design/elevation)用于理解层级，不能据此推断任意阴影实现都没有性能成本。

### 设置页作为首个样板

保留外观、阅读与交互及后续分组的顺序。设置项内部使用“说明占剩余宽度，控制项独立列”，说明容器允许自然换行。主题按钮组可在明确窄栏规则下移到下一行；开关项避免因为说明长短在左右和上下之间偶然变化。

局部草图提供两种外观：

- **分组清单，推荐**：在既有分组内，以一个安静的表面与细分隔组织设置项。相同的设置顺序和完整说明仍保留，开关形成稳定右边线。
- **独立卡片**：保留一项一卡的结构，统一每项内部排版。实现影响更小，但重复边框和纵向留白更多。

推荐先证明统一设置行的收益，再按实际截图决定是否采用分组表面。分组只影响视觉边界，不能使原本单独的点击区变成整组可点击，不能引入折叠或把设置藏起来。GPU 的读取失败、保存失败、待重启说明及“保存并重启”入口必须完整保留。

草图是会话内的外观探索，不连接应用设置。其主题按钮与开关仅用于检查局部状态；没有模拟 Mica、实际 GPU 状态或产品动画。不能拿草图替代 Electron 验收。

## 动画与功能的明确保护清单

以下数值取自当前源码，不能以 1.1.0 早期设计中的目标范围替代。

| 对象 | 当前基线 | 1.2.0 保护要求 |
| --- | --- | --- |
| 全局 motion 变量 | 120 / 160 / 200ms；`cubic-bezier(.2,.8,.2,1)` | 原值保留；各控件自身的 ease / ease-out 等声明也保留 |
| 页面切换 | opacity 140ms、transform 160ms、display 160ms allow-discrete；进入 y=6px，退出态 y=-4px | 属性、关键帧规则、display 保留及立即 inert/aria-hidden 不变 |
| 通用内容/浮层进入 | 内容从 opacity .3、y=6px；浮层从 opacity 0、y=-5px；160ms | 保留选择器、触发与挂载时机 |
| 通用退出 | 140ms，opacity 0、y=-5px；立即不可交互 | CSS 与 `useExitPresence` 的释放时间继续配套 |
| 分栏/导航外壳 | WAAPI 200ms；使用新旧 x 差，首次阅读外壳 +24px、其他外壳 -12px | 最终几何一次提交，不改成逐帧调整阅读宽度 |
| 标签新增/重排/关闭 | 新增与重排默认 180ms；新增 y=7px；关闭外壳 120ms、y=7px | 保留 ghost 克隆范围、惯用操作与清理；不复制漫画内容 |
| 原生工作区 dialog | 160ms，y=8px、scale(.99)，含 overlay/display 离散过渡 | 不替换成另一个模态原语，不统一覆盖动画 shorthand |
| 封面与章节反馈 | 网格封面 160ms ease-out；详情封面 250ms ease；收藏按钮 100ms；章节按下 scale(.97) | 保留已有差异，避免“统一样式”误改现有效果 |
| 加载与下载反馈 | 阅读加载环 900ms linear；下载进度使用 scaleX | 仅在既有条件下呈现，不新增装饰循环或改为布局动画 |
| 动画关闭/系统减少动态 | 即时取消活动动画；禁止过渡/平滑滚动；系统设置优先 | 两条开关路径及 GPU 设置独立性不变 |
| WAAPI 清理 | `duration + 64ms` 兜底 cancel | 保留遮挡/软件渲染恢复保护 |

关键几何也需要保护：标题栏 36px、导航 208/64px、阅读标签栏 44px、tabs 顶部 5px（与关闭 ghost 的定位配套）、工具栏 40px（常态与退场占位配套）、浏览/阅读最小宽度 300/480px、分隔条 6px、漫画页间隔 12px。窗口最小值和现有比例调整规则沿用。

不在阅读图片或 canvas 上增加 margin、border、CSS 缩放或布局占位阴影。保留滚动容器、page key、data 属性及事件绑定。新样式不得在菜单祖先上增加会改变 fixed/absolute 定位的 transform、filter 或 contain，也不使用 `transition: all`。`.manga-card` 的 paint containment 可能截断外扩阴影，优先使用现有边界与表面变化。

## 工程落点与数据边界

外观层仍由现有的主题状态驱动：应用设置 → store → FluentProvider 与 `.ui-light/.ui-dark` → 各组件静态样式。1.2.0 只完善最后两层的映射与呈现，不增加新的持久化设置、IPC、后台请求或主进程服务。

先给现有语义 CSS 与 Fluent Theme 建立明确对应表，再逐项落到 `winuiTheme.ts`、`surfaceStyles.ts`、`global.css` 和相关页面的 `makeStyles`。共用规则优先是小型静态样式或变量，不为统一视觉重构页面生命周期。动效变量和含动画/几何的样式块保持原值，不能用一个全局覆盖选择器吞掉它们。

组件内只调整需要修改的样式、纯呈现包装和已有图标。`ExperienceSettings` 的设置读取/保存、下载任务状态、阅读工作区串行保存、PageHost 缓存和 ReaderPage 虚拟布局继续使用原实现。原生 dialog 和 Fluent Dialog 保留各自的焦点及关闭机制，仅共享视觉角色。

失败处理也属于保留范围：加载失败仍展示原错误和重试入口；设置失败不显示已保存；阅读位置保存失败仍保留当前工作区；GPU 待重启与实际运行状态分开展示；下载失败保留真实阶段。错误、禁用和焦点状态不能因为“安静”而隐藏或变得不可辨认。

建议分小批落地：先冻结与记录基线，再完成主题/语义色及设置样板，随后迁移浏览/详情/下载等页面，最后精修阅读外壳和浮层。每批保持可独立审查和回退。出现回归时先撤回该批视觉改动，不借机改动保存、布局或动画算法来适配美化。

## 后续实施的验证与验收

### 基线先行

实施前用当前源码和固定合成内容，补齐首页、分类、搜索、收藏/历史、详情、下载、设置、诊断、新标签页、阅读器及菜单的截图。固定窗口尺寸、主题、缩放、数据及动作序列，避开个人阅读内容和不稳定网络数据。

记录关键动画的运行时 `getKeyframes()`、`getTiming()` / `getComputedTiming()` 与 CSS computed style，并与源码定义互相核对。旧版和新版使用相同几何与动作比较；分栏和重排的位移本来就依赖实际几何，应验证相同输入下的结果及计算规则，不能把某一次测得的任意距离写成通用常量。

新增视觉行为或可自动化修复遵守项目 TDD：例如设置行的明确对齐要求、品牌前景/背景配对，先有针对真实需求的失败证据，再改实现。动画保持测试在旧版理应通过，是兼容基线；不为制造红灯破坏它。纯色值、静态排版和图标微调使用适当的对比度计算、构建及实际截图检查，不声称补测等于测试先行。

验证矩阵覆盖浅/深两主题、Windows 100/125/150/200% 缩放、960×640 与常用大窗口、浏览全宽/三栏/阅读铺满/侧栏隐藏。实际浏览容器至少检查约 300、480、672px 可用宽度；不把窗口宽度误当成页面宽度。额外覆盖 Mica/纯色、动画开/关、系统减少动态、强制颜色、GPU 两种设置、快速打断与窗口遮挡恢复。

视觉验收要求：无非预期横向滚动、遮挡和操作区裁切；同类基线、间距、图标和表面一致；必要文字与状态有足够对比；原有信息与动作完整；不因增大留白而减少封面网格列数。对允许的换行与截断逐类确认，不以全页面像素完全相等作为美化验收。

功能与动画验收要求：基线动作均可完成，只有一个活动 reader；隐藏保留当前会话，后台不多挂图片；阅读锚点与保存失败路径不变；关键动效属性/时间/规则与基线一致；静置后没有新增常驻动画或图像节点。资源数据必须同设备、同构建、同内容对照，异常时调查原因，不预先承诺一个没有实测依据的性能百分比。

草图实际核验：两种方案均检查了 736px 宽的深色呈现与 320px 宽的浅色呈现，另检查分组清单的 480px 浅色呈现；主题切换、方案切换和开关本地状态更新可用。320px 视口下两方案的产品表面均为 `clientWidth=286 / scrollWidth=286`，未出现水平溢出；浏览器记录的 error/warn 为 `[]`。预览是普通浏览器中的局部 HTML，不是完整应用，也没有承诺与 Electron 动效一致。

建议审阅的核心决策是：采用精修 Fluent 的整体方向，先统一语义色与设置行，再扩展到全部页面；设置区域优先考虑分组清单，保留独立卡片作为较小改动的备选。产品实现需在本方案获得批准且用户要求实施后开始。
