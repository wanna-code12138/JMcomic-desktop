# JMComic Desktop 性能基线（2026-08-20）

## 结论

当前性能问题不在 TypeScript 或 Electron 本身，优先级最高的是三条具体路径：

1. 连续阅读模式的图片在取得固有尺寸前高度为 0，虚拟列表把所有页面压成约 4px 占位，`loading="lazy"` 因而可能永远不触发。
2. 在线冷加载受站点导航和 CDN 首字节支配；章节图片缓存未命中 p95 为 898.27ms，而磁盘缓存命中 p95 仅 0.80ms。
3. 下载数据库会保留 `completed` 状态，即使下载根目录已经不存在；界面仍显示“已下载”，打开后却是 0 页。

在这三项处理完并重新测量前，不建议迁移到 C#/WinUI 3、Rust 或其他技术栈。重写会显著扩大图片顺序与反打乱回归风险，却不能缩短远端站点的 2–3 秒导航时间。

- CPU：AMD Ryzen AI 7 H 350，8 核 16 线程
- 内存：31.1 GB
- Node.js：v24.18.0

- 热章节打开：10 次；滚动帧采样：15 秒 × 10 次
- 原始事件由主进程和 renderer 的 `[perf]` 结构化日志采集，使用 `scripts/summarize-performance.mjs` 汇总

## 已确认的根因

### 1. 连续模式的零高度懒加载闭环

现场 DOM 中 39 个 `<img loading="lazy">` 的 `naturalWidth`、布局宽高均为 0；对应 canvas 保持默认 300×150 且 `display:none`，父项高度只有 4px。虚拟列表无法获得真实高度，浏览器也不会为零尺寸懒加载元素发起请求。切换单页模式后，同一图片立即加载并成功反打乱为 720×3008 canvas。

这应通过“稳定的初始估算高度/宽高比占位 + 只渲染视口附近项目”解决，不能修改 `getNum`、条带坐标、绘制顺序或 `page_arr` 顺序。

### 2. 在线冷路径由网络主导

缓存命中与未命中的 p95 相差约 1123 倍（0.80ms 对 898.27ms）。当前章节进入时可以同时触发整章大量 `jmimg://` 请求；底层已有磁盘缓存，但自定义协议路径没有统一的请求调度和同 URL single-flight。

建议按优先级实施：

1. 首屏 1 页最高优先级，随后只预取前后 2–4 页。
2. 自定义协议增加同 URL single-flight，避免重复请求与重复写缓存。
3. 为未命中请求增加 6–8 的并发上限，并用基准选择最终值。
4. 缓存索引和失效策略保持 URL 到文件的一一映射；不要改变页面数组索引。
5. 章节页面数据继续使用现有内存缓存；首次抓取仍受目标站点限制。

### 3. 本地下载状态与文件系统不一致

数据库存在多条 `completed` 任务，例如 46/46 页，保存根目录统一记录为 `C:\Users\David\Downloads\JMComic`；现场该目录不存在。界面仍展示 4 部已下载漫画，打开章节则返回“章节目录中没有图片文件”。因此本轮无法取得有效的本地图片读取 p50/p95。

建议在展示下载列表和应用启动时做只读校验：目录不存在或图片数不足时显示“文件缺失/位置已变化”，不再计入“已下载”；提供重新定位根目录能力。不要自动删除数据库记录。

### 4. 数据库不是当前瓶颈

`sql.js` 全库保存 p95 为 1.58ms，在当前 69KB 数据量下无需为性能迁移数据库。数据增长到足以使保存超过 16ms 后，再评估批量写入或 SQLite 原生驱动。

## 技术栈判断

- 保留 Electron + React + TypeScript：当前瓶颈都有明确的 I/O、缓存或布局根因，迁移语言不会改善远端首字节。
- 继续使用 Fluent UI 组件，但界面视觉应由统一 token、排版密度、层级和动效约束完成；不需要为了“像 WinUI”切换到原生 WinUI 3。
- 若以后确需原生能力，只把边界清晰的热点做成原生模块；反打乱算法和页面顺序契约仍留在现有受测试保护的路径。

## 下一阶段验收指标

- 连续模式首次进入能稳定加载首屏，不能出现所有页面 0 高度。
- 缓存命中图片 p95 不高于当前 0.80ms 的 120%。
- 在线热章节打开 p95 从 469ms 降到 350ms 以下。
- 冷网络同时请求数受控，首屏图优先完成；整章排序完全不变。
- 下载目录缺失时不再显示为可直接阅读的“已下载”。
- 图片顺序、下载编号、`getNum` 与 canvas 条带绘制契约测试持续通过。

## 测量限制

- 目标站点列表在测量中发生过章节漂移，因此自动化选择“当前最后一章”而非固定 ID。
- Chromium 缓存清理后，同一 renderer 生命周期内相同 `jmimg://` URL 不会稳定重发；冷缓存采用本次真实缓存未命中的 64 个图片事件，没有伪造 10 次章节冷启动。
- 本地根目录缺失，无法形成有效的本地读取基线；修复状态一致性或重新定位目录后必须补测。
