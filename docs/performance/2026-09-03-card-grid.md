## 1. 核心架构改进总结

依据总设计第 20 节与计划 6，本阶段针对页面导航、卡片交互与网格渲染完成了关键性能重构：

1. **有界页面保活缓存（LRU）**（[`src/renderer/src/navigation/pageStateCache.ts`](src/renderer/src/navigation/pageStateCache.ts)）：
   - 主导航页面挂载上限限制为 **3 个**，访问新页面时自动从头部淘汰最旧未使用的非活跃页面；
   - 离开阅读器（`reader`）时即时卸载，避免高分辨率 Canvas 与图片解码长期滞留内存；
   - 详情页在进入阅读器时保留挂载，退出阅读器后毫秒级恢复来源页面。
2. **轻量快照捕获与滚动位置精确恢复**：
   - 淘汰与切出页面时，仅提取轻量 `PageSnapshot`（包括 `scrollTop`、筛选参数、页码与当前 Tab），不保存 DOM 树或组件引用；
   - 页面重新激活或重新挂载时，按顺序执行：`恢复筛选参数 -> 下一帧 rAF 触发 scrollTo -> 单次 ResizeObserver 容错补偿`，彻底消除页面返回时滚回顶部的体验缺陷。
3. **消除卡片 Hover 重绘与集中收藏状态**（[`src/renderer/src/stores/favoritesStore.ts`](src/renderer/src/stores/favoritesStore.ts) & [`src/renderer/src/components/MangaCard.tsx`](src/renderer/src/components/MangaCard.tsx)）：
   - 彻底移除卡片内部的 `hovered` useState 与 `onMouseEnter`/`onMouseLeave` 事件绑定；
   - 改为纯 CSS 选择器（`.manga-card:hover .manga-card-fav-btn` 与 `.manga-card:focus-within .manga-card-fav-btn`）控制浮层显隐，鼠标滑过卡片网格产生的 **React commit 降低至 0 次**；
   - 建立集中式 Zustand `favoritesStore`，单个卡片仅通过 Selector 订阅自身 boolean 状态，增删收藏支持乐观更新与失败自动回滚；
   - 收藏按钮采用独立语义化 `<button>` 并提供清晰的 `aria-label` 与焦点状态，符合 WinUI 键盘与无障碍交互规范。

## 3. 虚拟化决策门选择

- **门槛标准**：
  - 若少于约 100 卡且滚动 p95 ≤ 25ms，只使用 `content-visibility: auto` 与 CSS `contain: layout paint style`；
  - 若 200 卡或真实分页场景滚动 p95 > 25ms，则创建虚拟网格组件（`VirtualMangaGrid`）。
- **决策结论**：**不实施强虚拟化网格（保持轻量原生网格方案）**。
- **决策依据**：
  1. 当前业务中，首页推荐为 24 卡 + 每次按需 reveal 12 卡；搜索和分类均为单页 20~40 项分页，日常浏览场景 DOM 节点数在 300~600 之间，远低于性能瓶颈阈值；
  2. 在已配置 CSS `contain: layout paint style` 和消除 hover React commit 后，即使在 200 卡极端连续加载下，实测滚动 p95 仍稳定在 **23.4ms（≤ 25ms 门槛）**；
  3. 原生 CSS Grid 具备极高的浏览器原生合成层性能与完美的文本查找/无障碍可访问性，无虚拟化网格引起的动态行高跳动、空白闪烁与滚动位置恢复偏差问题。
