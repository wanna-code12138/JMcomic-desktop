# JMComic 项目收敛与阅读器改进方案

日期：2026-09-28。本文第 1–12 节保留实施前的审计与批准设计；用户随后批准实施，当前结果见 [2026-09-29 实施与验收报告](2026-09-29-implementation-results.md)。第 13 节为后来新增的三栏布局设计，尚待确认。

审计基线：`main@4a78cc6`。另核对 `fix/performance-runtime-completion@8e8c057`、`codex/cleanup-abandoned-files@f56bafa` 及账号分支的 Git 包含关系，对部分模块做隔离复现。审计阶段只提交了这份报告；下述“当前”“尚未”等表述均指当时的基线，不覆盖后续实施记录。

## 1. 判断与第一性原理

当前最需要的是收敛已有成果、修正用户可见行为，再围绕真实瓶颈优化。许多性能工作停留在未合并分支；部分新增抽象没有业务调用；现有测试又以源码契约为主，容易出现“组件测试通过，但产品路径仍未改变”的情况。

阅读器的核心价值可以压缩为四条：

1. 用户能尽快找到作品并看到第一张正确图片。
2. 连续阅读时位置稳定、切页顺手、等待可预期。
3. 续读位置和离线文件可靠，失败有可操作的恢复路径。
4. 实现复杂度与这些价值相称，每一层缓存、回退、状态和后台任务都有清楚的责任与退出条件。

删行数、删分支数不能代表产品变好。分支标签清理主要减少认知负担；真正的运行性能取决于业务调用链。消融也不能仅凭一次正常网络测试认定某条回退“无用”。

沿用 Electron、React、Fluent UI 和既有内容网关。现阶段没有足够证据支持更换技术栈、全面重写数据库或强行迁移 Canvas 到 Worker。

本次还用项目已安装的 `@tanstack/virtual-core` 运行了与阅读器同样的 overscan 选择方式：


这是库行为的实际复现：渲染范围首项不等于可见范围首项。它支持阅读器页码算法存在问题的判断，但尚未代替真实 Electron 阅读流程回归。

### 三个隔离行为复现

读取当前源码或通过 `git show` 读取性能 tip，用已安装 TypeScript 转译后在 Node VM 中执行。仅替换 Electron、网络与文件系统端口，不改被测业务实现。主审计已独立复跑以下实验：

```json
{"ref":"main","simulatedFailures":2,"finalStatus":"completed","reportedPages":2,"totalPages":2}
{"ref":"fix/performance-runtime-completion","simulatedFailures":2,"finalStatus":"completed","reportedPages":2,"totalPages":2}
{"ref":"fix/performance-runtime-completion","configuredMaxBytes":128,"observedSerializedBytes":1125,"io":"in-memory fake filesystem, no files written"}
```

输入分别是：两页都返回 HTTP 500 的下载结果；`maxEntries=1000`、`maxBytes=128` 的缓存写入 1024 字符条目；同一个 key 的两个图片消费者，只取消第一个，再让共享任务成功返回。这些实验确认逻辑缺陷，不等于真实网络、磁盘或 Electron 界面端到端测试；未写入个人数据。

### 尚未验证的部分

- 未合并性能分支本次做了代码、调用图与上述局部隔离复现，没有重跑它的完整测试或网络实测。分支内旧报告的 49 文件通过、网络耗时和性能数字不作为本次结果。
- 没有启动产品做逐页视觉检查，没有采集当前真实网络 p50/p95、滚动帧时间、峰值内存或长期稳定性数据。
- 未 fetch；`origin/main` 是本地保存的远端引用，不能据此断言服务器当前状态。
- 未删除文件、分支、stash、提交；未改配置或业务代码，未合并 main，未推送。

## 6. 收敛后的职责与数据流

保留既有能力，只在真实边界上整理职责：

```text
用户意图与页面组件
    ↓ 共享 DTO / 有类型的 IPC / requestId
阅读会话：章节身份、页序、当前位置、展示模式、待保存进度
    ├─ ContentGateway → 匿名 API / 直接网页 / 浏览器回退
    ├─ 图片服务 → 稳定图片身份、优先级、去重、取消、缓存、校验
    ├─ 渲染适配 → 解码/反打乱、可见范围、图片错误与重试
    └─ 个人数据服务 → 进度、收藏、下载清单 → 持久化协调器

下载任务 → 同一内容身份与图片请求策略
         → 页级下载/校验/反打乱/原子写入 → 完整性清单
```

- 一个状态只有一个拥有者。UI 展示状态不能顺便承担下载完成判断、网络恢复和数据库事务。
- 内容请求以章节身份和 requestId 关联；返回旧章节结果不能覆盖新会话。页面取消与网络订阅生命周期一致。
- 图片身份与优先级分离。滚动使优先级变化时更新调度任务，避免为修改优先级不断改变 img src，引起重复加载或闪烁；多消费者共享任务时，只移除已取消的订阅者。
- 在线阅读与下载共享可复用请求、校验和缓存策略，各自保留显示与文件输出适配；不把阅读强制改为“整章下载完再显示”。
- 阅读进度至少有章节身份、页索引和页内位置；模式切换、窗口变化时按锚点恢复。旧记录兼容为页内位置 0。
- 数据保存先接通真实调用，再做合并与原子落盘。只有 export 的测量成本仍显著，才单独评估数据库工作线程或文件型 SQLite。
- 回退仅在实际失败时发生，明确超时、重试、冷却和错误类别。缓存写失败通常不应毁掉已经可用的内容；个人数据保存失败必须可感知、可重试。

不引入通用插件框架、事件总线或过度分层。`ReaderPage` 按会话加载、进度持久化、图片展示、工具栏/手势拆分即可；先以行为测试守住调用链，再移动代码。

## 7. 成熟阅读器的体验范围

第一轮阅读器交付应围绕完整使用闭环，而不是把控件换一套颜色：

- **进入与续读**：作品/章节/页码清晰，首图就绪立即可读；恢复真实阅读位置，切换模式不跳回旧 resume 页；模式与缩放偏好持久保存。
- **沉浸与尺寸**：全屏、侧栏收起、工具栏自动隐藏；适宽、适高、原始尺寸、最大阅读宽度；工具栏隐藏不得造成正文尺寸反复跳动。键盘焦点或弹窗打开时不自动隐藏。
- **连续性**：页码跳转、缩略图导航、上一章/下一章；滚动、单页共享进度语义。跨章预取只取必要元数据/少量相邻页，并受预算约束。
- **输入**：鼠标滚轮、键盘、拖拽、触控板/Pointer 输入一致；左右阅读方向可选。双页模式作为后续增量，需处理封面独页及横跨页图片。
- **失败恢复**：每页有加载、失败、重试反馈；某页失败不遮住整章；下载按钮展示实际状态。用户提示说清可执行操作，技术错误放到可展开详情。
- **观感与动画**：沿用现有中性色 Fluent tokens、统一间距、封面比例、中文排版和控件状态；用短过渡表达状态变化。现有 reduced-motion 保留；阅读正文优先位置稳定，不使用干扰内容的移动或炫光。
- **可访问性**：原生按钮语义、完整键盘操作、可见焦点、快捷键避开输入框/弹窗；检查高 DPI、窄窗口、深浅主题和高对比需求。

这部分是建议设计，不是对当前视觉截图的验收结论。实施前后使用同一套合成页/获准测试内容，在 100%/125%/150%/200% 缩放与常见窗口尺寸下进行对比。

## 8. 可回滚的消融实验

先建立基线，再一次改变一个因素；交互耦合明显的因素追加组合实验。实验开关是开发工具，稳定后删除，避免永久叠加双路径。

| 实验 | 对照与变量 | 观察什么 | 何时简化 |
| --- | --- | --- | --- |
| 旧无调用入口 | 保留 / 删除明确无调用 extractor 与旧账号 UI | 编译、关键场景、依赖图、打包产物 | 功能和恢复路径不变，且没有动态入口证据 |
| 内容回退 | 匿名 API、直接 HTML、浏览器的成功/失败夹具；分别禁用一层 | 正确结果、首批内容时间、错误恢复率 | 仅在目标场景故障矩阵证明不再需要某层时删；正常网络快不能单独构成依据 |
| 缓存层 | 冷缓存、内存命中、磁盘命中；逐层关闭 | 首图、实际网络字节、磁盘写量、RSS、失效正确性 | 缺乏收益且增加状态/一致性成本的层才移除 |
| 预取与并发 | 无预取 / 相邻 1 页 / 相邻 2–4 页；有界并发参数 | 翻页等待 p95、浪费下载字节、取消延迟、错误率 | 选收益稳定且资源较低的窗口，禁止无界整章预取 |
| 页面保活 | 不保活 / 返回页保活 / 当前有界策略 | 返回位置、返回耗时、DOM、RSS、后台任务 | 用保存页面状态替代不必要的常驻组件 |
| 反打乱执行位置 | 当前 Canvas 基线；仅在 CPU 热点成立时比较 Worker | 完整首图耗时、帧间隔、传输复制、峰值内存、逐像素一致 | Worker 的端到端收益超过复杂度后才采用 |
| DB 保存 | 当前业务直写 / 接通有界合并与关键 flush | 每分钟 export 次数、耗时、退出和故障恢复 | 保留确有收益且满足持久性约束的实现 |
| 视觉与动效 | Mica 开关、无过渡 / 短过渡 | 全帧间隔、输入响应、低功耗负担、视觉一致性 | 移除造成明显帧成本而无信息价值的效果 |

测量矩阵覆盖冷/热启动、离线/限速/失败、长图/横图/长章节、大收藏/下载记录、边看边下载、窗口缩放、快速换章、退出重开。使用固定夹具验证正确性，用受控服务验证资源与故障，再做少量真实网络验证，避免将第三方服务波动误判为应用收益。

首轮每个组合至少 10 次用于筛选；有价值方案再做 50–100 次交错 A/B 复测。10 次数据仅作为探索，不能包装成稳定 p95。给每个报告记录 commit、依赖版本、硬件、网络、样本数、缓存状态和原始日志位置。

**指标定义与建议门槛（目标，非本次实测）：**

- 图片顺序、反打乱、完整性、数据恢复全部通过；性能收益不能兑换正确性。
- 首张可见计时终点在真实图片解码和反打乱后完成显示；收到响应头不能算首张可见。
- 本地/热缓存章节首图初始目标 p95 ≤ 300ms；在线指标按元数据、排队、网络、解码、绘制分别计时，同网络 A/B 验收，不承诺第三方网络绝对时延。
- 60Hz 场景目标全帧间隔 p95 ≤ 25ms，并报告慢帧比例。只采慢帧的分布不能冒充全帧 p95。
- 长时阅读和重复进出页面后内存应收敛；以任务与图片字节预算约束资源，不只限制请求个数。
- 性能提升须超过试验噪声；若主要指标或故障成功率退步，回滚或给出明确取舍再审阅。

## 10. 另外值得投入的方向

- **离线可信度**：页级清单、缺图修复、下载进度实数、可移植 CBZ 导出。当前目录依赖作品/章节标题，应逐步以稳定 ID 区分同名内容；迁移必须保留旧目录映射与恢复方案，不能直接重命名用户下载。先保证本地完整阅读，再评估通用格式导入。
- **资源与可恢复性**：可区分“可再生缓存”和“个人数据”的容量管理；备份恢复与升级迁移演练；磁盘不足、退出过程中写入失败都有明确结果。
- **诊断可用性**：保留已有本地诊断，记录正确的端到端指标、回退原因和失败阶段；日志脱敏、限量、可一键导出。不要让用户阅读内部报错来猜下一步。
- **长期可维护性**：依赖升级、版本兼容和发布验证形成固定节奏；消除依赖转引入、文档与脚本不一致等小债务。检查现有方案后再新增工具。
- **边界清楚**：匿名浏览与账号能力保留明确边界；旧账号分支不能因为“提交较多”自动进入本轮产品。账号范围应另行确定。

## 13. 2026-09-29 布局修订：三栏阅读工作区

状态：依据用户新提供的 Codex 截图补充，待确认后实施。本节替代第 7 节中整页阅读器的外壳设计，其余已批准的可靠性、离线库、清理和性能工作继续执行。前面的审计数字保留为历史基线。

### 目标与布局

```text
普通浏览：  [ 图标 + 导航文字 208px ][ 浏览 / 作品详情                    ]
进入阅读：  [ 图标导航 64px ][ 浏览 / 作品详情 ][ 作品 A × | 作品 B ×     ]
                           [ 章节、收藏等操作 ][ 工具栏与当前章节正文      ]
铺满窗口：  [ 阅读标签与还原按钮                                      ]
           [                     阅读器                               ]
```

- 左侧导航常驻，首次进入阅读自动收成图标栏；按钮保留中文提示、可访问名称、当前项和键盘焦点，用户可以手动展开。沿用现有 Fluent SVG，不新增图片或图标依赖。
- 中间保留当前作品详情和浏览上下文；可以继续浏览首页、搜索、收藏、下载和设置，不关闭右侧阅读器。打开另一作品的章节会增加右侧标签。
- 右侧标签按作品与在线/本地来源区分；同一本书换章复用标签，再次打开相同章节直接激活已有标签。标签可切换、关闭；关闭当前标签激活相邻标签，关闭最后一个恢复普通浏览及展开导航。
- 默认右侧占剩余内容宽度约六成；中间至少 300px，阅读区至少 480px。960px 的最小窗口仍能操作。详情页封面、按钮和章节列表按容器宽度重排；阅读器窄栏使用紧凑工具栏，次要设置收进菜单，保留页码与常用控制。
- “铺满窗口”隐藏导航和中间区，让右侧阅读器占据标题栏以下全部空间；同一按钮恢复三栏及位置。“系统全屏”仍独立控制，Esc 先退出系统全屏，再退出铺满状态。切换不会重开章节或重置缩放。
- 这一轮不增加拖动分隔线、双页模式或重启后自动恢复全部标签；既有阅读历史和偏好持久化继续支持冷启动续读。

### 状态与生命周期

- `appStore` 负责中间页面、详情作品、阅读标签元数据、活动标签和铺满状态。`ReaderState` 保留章节和续读锚点，不保存 DOM、图片或 Canvas。
- 标签变更由一个串行过渡入口管理：等待当前会话保存页码、页内位置和偏好，记录锚点，再激活/关闭/换章。过渡期间避免重复点击产生两个并发保存；保存失败留在当前标签并提供重试，不能静默丢失位置。
- 只挂载活动标签的阅读会话。后台标签仅保留元数据和阅读锚点，撤销图片订阅、事件与 Canvas；恢复时复用已有缓存。中间页面保活仍沿用最多三个主页面的现有策略。
- 阅读快捷键仅在阅读区域拥有焦点时生效；中间搜索框、详情按钮和导航键盘操作不触发右侧翻页。窗口关闭沿用已有 renderer 保存确认及后台任务排空流程。
- `AppFrame` / `PageHost` 分开承载中间页面和右侧工作区；不再让 `currentPage='reader'` 同时代表整页导航和阅读会话。IPC、内容网关和下载协议保持现有职责，无新依赖和数据库迁移。

2. 实现工作区状态和过渡入口；接入现有阅读会话保存、清理机制，再调整三栏外壳、SVG 导航、标签及工具栏。
